# Step 5｜記事の型（ページ種別テンプレート）

作成日: 2026-08-16
適用: W1以降のすべての改稿・新設記事。既存記事はウェーブ内で触るときに型へ寄せる。

## 共通ルール（全型）

1. **診断ファースト** — 読者が最初に出会うのは「あなたはどれですか」の分岐。全文を読ませない。luggage-airport（2026-08）で実証した構成を標準とする
2. **事実は fact ショートコード** — 料金・時刻など data/travel_facts.yaml にある値は必ず `{{</* fact "..." */>}}` で参照。新しい事実を書くときは yaml に追加してから使う（出典URL・確認日必須）
3. **多言語同一構造** — 見出し・表・分岐の構造は5言語で一致させる。タイトル・見出しの語彙は zh-tw / en の検索意図を先に決め、ja が追随する
4. **2クリック網** — 記事末尾に「柱ハブへ戻る」＋関連スポーク。孤立記事を作らない
5. **収益合流** — 柱1・2の記事は個別ホテルページへの合流点を必ず持つ。柱3・4は軽い戻り導線のみ
6. **frontmatter規約** — `noDate: true`／`tgNav: true`／`factChecked`／FAQ 3〜5問（FAQ内では fact 不可＝リテラル記載、更新時は yaml と同時に直す）

## 型1: ハブ型（柱の入口）

対象: トップ／hotels/_index／access-guide／tourism

```
リード（2〜3文。柱の約束）
→ 診断分岐（「いま、どの状況ですか」— 状況×行き先の表 or カード）
→ 柱の主要トピック（各スポークへ 1トピック=1リンク+1行説明）
→ 例外・注意（この柱でよくある落とし穴）
→ 関連柱への横リンク
```

- ハブは**自分では詳細を語らない**。分岐と要約だけを持ち、詳細はスポークへ
- 例外: access-guide は「ハブ兼記事」（検索実績があるため、①地図②行き方の本文を保持したままハブ機能を足す）

## 型2: 比較型（テーマ記事）

対象: budget／kids／shuttle／facilities／where-to-stay

```
リード（誰のための比較か）
→ 診断分岐（読者の条件で節へ飛ばす）
→ 比較表（1行1選択肢・推奨列つき。モバイルで最重要列が初期表示に入る列順）
→ 条件別の深掘り節
→ 個別ホテルページへの合流（実名リンク）
→ 関連ページ
```

## 型3: 手順型（ハウツー）

対象: luggage-howto／luggage-airport／disney-tickets

```
リード（できること・2つの落とし穴）
→ 診断表（自分の状況→使う手段。締切・場所・リンク列つき）
→ 手段別の詳細（安い順 or 状況順）
→ 「間に合わなかったら」（必ず置く。行き止まりにしない）
→ まとめ節（判断に必要な数字だけ再掲）
→ 関連ページ
```

## 型4: 個別ホテル型

対象: 45軒（今回の再設計では**構成変更なし**・CLAUDE.md 既存ルールを維持）

- 「おすすめしない人」節の維持／価格は「2名1室・通常期の目安」明示
- 変更点は1つだけ: 共通事実（リムジンバス運賃等）を記事更新のタイミングで fact 参照に置換

## 型5: スポット型（滞在柱の単一スポット）

対象: kasai-rinkai-park／teamlab-planets／urayasu-traffic-park／maihama-eurasia-spa

```
リード（パークとの位置関係・所要時間を最初に）
→ 本文（現状構成を維持）
→ 末尾: 滞在ハブ（tourism）へ戻る＋「この近くに泊まるなら」1リンク
```

## 表記の統一

- 時刻は24時間表記「9:50」「13:00」／料金は fact 参照（手書きする場合は税込明記）
- 「※要確認」を本文に書かない（CLAUDE.md）。確認できないことは書かない
- 診断分岐のラベルは「読者の状況」で書く（○「成田 第3ターミナルに着く」／×「LCCについて」）
