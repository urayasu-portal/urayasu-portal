### 季節性に注意

ベースライン期間は**夏（6〜8月）**を含んでいる。浦安の夏は花火大会・盆踊り・夏休みイベントで検索需要が跳ね上がるため、秋の数字と単純比較するとサイト全体では必ず「減った」ように見える。

したがって判定は次の順で行う。

1. **CTR の変化**（季節性の影響を最も受けにくい。改題の効果はここに出る）
2. **平均掲載順位の変化**
3. クリック・表示回数（参考。増減の理由を季節要因と切り分けてから読む）

Phase 3 の申し送りどおり、**16か月分のページ別データ**（Group by: Page + Date）を同時に取ると前年同月と比較でき、季節性を切り分けられる。

### 判定できないもの

- **新規2記事**（ダイソー・京葉線）はベースラインが存在しない。単純に「10月時点で何クリック取れたか」を見る
- **ガイド導線の拡張**（Phase 3 A-1）は GSC では測れない。GA4 の「記事 → ガイド」遷移率で見る（ベースライン: 8.5% / 1.9%）
- **画像最適化**は GSC の「ウェブに関する主な指標」で見る。10月上旬に取得予定

## 4. Phase 4 で見送った項目とその理由

| # | 施策 | 見送りの理由 |
|---|---|---|
| 5 | ページ送り canonical の自己参照化 | **データが支持しなかった。** バックログでは「インデックス未登録268件に効く可能性」としたが、GSCの内訳を見ると「代替ページ（適切な canonical タグあり）」は **25件のみ**。ページ送りページは221あるので、canonical が原因で大量に除外されているわけではない。268件の内訳は「検出 - インデックス未登録」187件と「クロール済み - インデックス未登録」81件で、これは canonical ではなくコンテンツ評価の問題 |

## 5. 今回取り下げた指摘

### モバイルで表が切れる（03-backlog 2-2）→ 誤診だった

Phase 3 で「素の `<table>` を使う posts 79本でモバイル時に表の右端が切れる」と報告したが、**誤りだった**。詳細は `03-backlog.md` の 2-2 に記載。

要点は3つ。

1. テーマの CSS リセットに `table { overflow-x: auto; }` があり、**サイト上のすべての表は最初からスクロールできる**
2. `scrollWidth > clientWidth` を「切れている」と読んだのが誤り。この状態は「その要素の中でスクロールできる」という意味
3. Phase 4 で一度 `@media (max-width: 700px)` のルールを追加したが、既存ルールと重複するだけなので**取り消した**。記事79本にも手を入れていない

**判定方法を改めた**: 「切れている」と言う前に、`element.scrollLeft` に値を入れて読み返し、実際に中身が動くことを確認する。

## 6. 検証結果（2026-09-06 時点）

- `rm -rf public resources && hugo --minify` で ERROR 0件
- 内部リンク先 3,680件中、リンク切れ **1件**。これは `/tools/post-tool.html` 内のテンプレート変数 `${slug}` で実リンクではない（運営者の判断でツールは現状維持）
- **`/travel-guide/pre-trip-checklist/`（ja）への404リンクは解消**（3本 → 0本）
- `/travel-guide/` ハブへの本文被リンクが 0本 → **3本**（Phase 1 でオーファンと判定していたページ）
- `static/images` に1MB超のファイル 0枚、拡張子と中身が食い違う画像 0枚
- 全ページに `livereload.js` の混入なし

### ビルド検証の注意（今回学んだこと）

**`public/` を検証に使う前に必ず `rm -rf public resources` してから `hugo --minify` する。** 理由が2つある。

1. Hugo は出力先の古いファイルを消さない（Phase 1 で誤判定した原因）
2. `.claude/launch.json` のプレビューサーバーは `hugo server -D -F` で起動しており、**draft と未来日付の記事まで `public/` に書き出す**。Phase 4 でも一度、`draft: true` の `pre-trip-checklist`（ja）が `public/` に存在して混乱した

プレビューサーバーを立てた後の検証は特に危険なので、サーバーを停止してからクリーンビルドし直すこと。
