# SEO監査 Phase 1 — 技術監査

実施日: 2026-09-04
対象: `hugo --minify` でビルドした `public/` 全体（HTML 3,884ファイル ＝ 実ページ 2,543 ＋ エイリアス 1,341）
手法: ビルド成果物の全数機械チェック ＋ 本番サイトのブラウザ実測 ＋ `content/**/*.md` のリンク解析
スコープ: 診断のみ。記事本文・frontmatter・テーマの変更は行っていない。

## 0. 結論

**サイトの技術的土台は良好**。内部リンク切れ 0件、構造化データ 1,079ページに実装済み、画像 alt 欠落 0件、h1 重複 0件、hreflang の言語コード表記も正しい。8月の再設計で入れた「薄いタグページの noindex」も設計どおり動いている。

一方で、**流入の92%を占める posts が資産（ガイド）に接続されていない**という構造問題が残っている。またテンプレート側で一括修正できる小さな漏れが5件ある。

優先度の考え方は「一括修正で効くもの → 影響が大きいもの → 個別対応」の順。

## 1. 一括修正できるもの

### A-1. posts からガイドへの導線が2割しかない【最優先】

| 指標 | 実測 |
|---|---|
| 関連ガイドカードが表示されている posts | 127 / 597（21%） |
| 本文中からガイドへリンクしている posts | 0 / 616 |

**影響の見立て**: 大。GSC 8月時点で posts はクリックの92%（4,033/4,371）を集めているのに対し、travel-guide 全体は4%（171）。posts はサイト最大の入口だが、そこから常設ガイドへ渡す経路が5記事に1記事しかない。残る470記事の読者は、記事を読み終えるとグローバルナビ以外の行き先がない。

CLAUDE.md の「posts⇔ガイド連携」は仕組みとしては正しく動作している（`related-guide.html` が `data/guide_map.yaml` のタグ一致で1件だけカードを出す）。カバー率が低いのは仕組みの故障ではなく、**マッピング表のタグ語彙が実際の記事タグに追いついていない**ため。

**修正方法**: `data/guide_map.yaml` の `tags:` を実タグに合わせて拡張する。テンプレート変更は不要で、yaml 追記だけで反映される。ただし CLAUDE.md が明示するとおり「イベント」「開店・閉店」「グルメ」などの大票田タグは意図的に除外されている（カードが出すぎるとノイズになるため）。ここを緩めるかどうかは判断が必要（→ 6章）。

参考として、posts に実際に付いているタグの上位は次のとおり。

| タグ | 記事数 | guide_map 対応 |
|---|---|---|
| 浦安市 | 198 | なし |
| 新浦安 | 87 | なし |
| 舞浜 | 78 | なし |
| 浦安 | 73 | なし |
| イベント | 62 | 意図的に除外 |
| 夏休み | 41 | なし |

タグは全842種類で、うち587種類（70%）は1記事にしか使われていない。マッピングで効くのは上位の数十種類に限られる。

### A-2. 画像が未最適化【高】

| 指標 | 実測 |
|---|---|
| `public/images` 合計 | 60MB / 113枚 |
| 平均 | 547KB |
| 1MB超 | 21枚 |
| 最大 | 5,490KB（`img_0373.jpeg`） |
| Hugo の画像処理実行数 | 0件（ビルドログ「Processed images: 0」） |
| フォーマット | jpg 62・png 34・jpeg 12・webp 5 |

**影響の見立て**: 中〜大。本番の記事ページを実測したところ、1ページの転送量2,057KBのうち2,042KBが単一のカバー画像だった（`/posts/wheelchair-basketball-3x3-court-open/`）。LCP要素はテキストなので LCP自体は580msと速いが、モバイル回線ではこの2MBが帯域を占有する。

**修正方法**: 一括。Hugo の画像処理（`.Resize` / `.Process "webp"`）をカバー画像テンプレートに入れ、幅1200px上限・webp出力にする。元画像はそのまま置いておける。1MB超の21枚だけ先に処理しても効果の大半が取れる。

### A-3. `<img>` の width/height 欠落【中】

posts 597ページの `<img>` 1,196個のうち、width と height の両方を持つのは597個（50%）。`loading="lazy"` はほぼ全数に付いている。

**影響の見立て**: 小〜中。本番実測の CLS は 0.077 で基準値0.1未満に収まっているが、余裕は小さい。画像読み込み前の高さが確保されていない箇所がレイアウトシフトの原因になる。

**修正方法**: 一括。画像を出力しているテンプレートに、Hugo の画像処理で得た `.Width` / `.Height` を出力する。A-2 と同じ改修で同時に片付く。

### A-4. 内部ツール2つが本番公開・robots.txt 許可【中】

| URL | 本番ステータス | robots meta | sitemap | 実体 |
|---|---|---|---|---|
| `/admin/` | 200 | なし | 非掲載 | Decap CMS 管理画面 |
| `/tools/post-tool.html` | 200 | なし | 非掲載 | 記事投稿補助ツール（55KB） |
| `/__tmp-coord-editor/facility-coord-editor.html` | 404 | なし | 非掲載 | ローカルビルド残骸のみ・本番影響なし |

`robots.txt` は `Allow: /` のみで、これらを除外していない。

**機密の混入はない**ことを確認済み。`post-tool.html` に現れる `ghp_xxxx` は利用者が自分の Personal Access Token を貼るための表示例で、実トークン形式（`ghp_` + 36文字）の文字列は0件。`/admin/` は Netlify Identity 認証で保護される Decap CMS の標準構成。

**影響の見立て**: 小。リンクもサイトマップ登録もないため通常はクロールされないが、インデックスされた場合に低品質ページとして評価対象に入る。

**修正方法**: 一括。`static/robots.txt` を用意して `Disallow: /admin/` と `Disallow: /tools/` を追加するか、両ファイルに `<meta name="robots" content="noindex, nofollow">` を入れる。`__tmp-coord-editor` は `public/` の残骸なので、ビルド前クリーンで消える。

### A-5. ページ送りページの canonical が1ページ目向き【低】

221件のページ送りページ（`/posts/page/2/` 等）が `index, follow` でありながら canonical を1ページ目に向けている。

```
/categories/お知らせ/page/2/
  robots    = index, follow
  canonical = https://urayasu-portal.com/categories/お知らせ/
```

**影響の見立て**: 小。Google は現在ページ送りに自己参照 canonical を推奨しており、2ページ目以降を1ページ目に集約すると、そこからしか辿れない記事の発見が遅れる可能性がある。ただし当サイトはサイトマップに全記事が載っているため実害は限定的。

**修正方法**: 一括。canonical を自己参照に変える（テンプレート1行）。なお、ページ送りページがサイトマップに含まれていないのは正しい設計で、変更不要。

## 4. 計測メモ（再現手順）

- **抽出**: `hugo --minify` 後、`public/**/*.html` 3,884件を gawk で全数パースし TSV 化（path / alias判定 / lang / title / titleLen / description / descLen / canonical / robots / hreflang数 / JSON-LD型 / img数 / alt欠落数 / og:image / h1数）
- **文字数**: `LC_ALL=en_US.UTF-8` 下の `length()` によるコードポイント数。全角1文字＝1
- **エイリアス判定**: `http-equiv="refresh"` の有無。1,341件を集計から除外
- **JSON-LD**: `--minify` は `application/ld+json` の中身を圧縮しないため、`"@type": "` は**コロンの後に半角スペースが入る**。ここを詰めたパターンで検索すると全件0になるので注意
- **被リンク**: `content/{travel-guide,life-guide}/**/*.md`（ja のみ）本文の `href="/..."` と `](/...)` の**両形式**を集計。ナビ・カード・list テンプレートは含まない。生活ガイドは HTML の `href=` 形式が主で、markdown 記法だけを見ると全件0になる
- **URLの突合**: ファイル名ではなく**ビルド後の実URL**で行う。`access-guide.md` の実URLは `/travel-guide/urayasu-maihama-access-guide/` のようにずれる例がある
- **リンク切れ**: index対象ページから出る内部リンクをユニーク化し、パーセントデコード後に `public/` 上の実体を確認
- **サイトマップ差分**: `public/*/sitemap.xml` の `<loc>` をデコードし、robots が noindex でない実ページ集合と `comm` で比較
- **本番実測**: ブラウザで `PerformanceObserver`（`buffered: true`）により LCP と CLS を取得。キャッシュが効くと `transferSize` が0になるため、転送量はディスク上の実サイズを正とした
- **PageSpeed Insights API はキーなし共有枠が枯渇（HTTP 429）で使えなかった**。フィールドデータは Phase 0 の GSC「ウェブに関する主な指標」エクスポートで代替する

## 6. 決めてほしいこと

1. **A-1 で大票田タグを解禁するか**。CLAUDE.md は「イベント」「開店・閉店」「グルメ」を意図的に除外している。ただし未対応タグの上位は「浦安市」198件・「新浦安」87件・「舞浜」78件といった地名タグで、ここに触れないとカバー率は2割から大きく動かない。案は3つ。
   - (a) 地名タグに汎用カード（生活ガイドトップ／旅行ガイドトップ）を割り当てる
   - (b) 複合条件（地名＋テーマ）を `guide_map.yaml` で表現できるよう `related-guide.html` を拡張する
   - (c) 現状維持とし、テーマ系タグの取りこぼしだけ拾う
2. **A-2 の適用範囲**。1MB超の21枚だけ先に処理するか、113枚すべてをパイプラインに載せるか。前者は当日で終わり、後者はテンプレート改修を伴う。
3. **B-2 の重複記事をどう統合するか**。4組それぞれで「残す方」を決める必要がある。新しい方に寄せるか、先に公開して被リンクが付いている方に寄せるかの方針。
4. **A-4 のツール公開をどうするか**。`/tools/post-tool.html` は運用で使っているなら残す必要がある。noindex だけ付けて公開を維持するか、リポジトリから外して手元運用にするか。
