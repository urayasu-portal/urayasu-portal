### 4.2 検証の変更点

| 項目 | 改修前 | 改修後 |
|---|---|---|
| frontmatter の解析 | 正規表現（`^---\n…\n---`）。BOM・CRLF で失敗、インライン配列のカテゴリは未検査 | 専用の解析器。BOM・CRLF・CR を正規化、ブロック／インライン配列、引用符・エスケープ・コメント、ネストしたマップ（cover・sources・faq）に対応。閉じていないクォート・項目の重複・タブ字下げ・解釈できない行を行番号付きで検出 |
| 投稿内容の正規化 | なし | 先頭 BOM の除去・改行の LF 統一をしてから検証・投稿 |
| title | 未検査 | 必須 |
| date | 未検査 | 必須・形式・実在する日時を検査。タイムゾーン無しは UTC 扱いになる旨を警告。ファイル名の日付と日本時間の date の不一致を警告 |
| 未来の date | 未検査 | **禁止しない**。予約投稿として公開予定時刻（日本時間）を表示し、確認を求める（30日より先は誤入力の可能性として強めに警告）。投稿後のメッセージにも表示 |
| slug | 未検査（無いとファイル名だけ slug 部分で作られた） | 新規は必須・形式（半角英小文字・数字・ハイフン）。**既存記事の更新では slug 無しを許容**（後方互換） |
| URL 重複 | 未検査 | ① GitHub 上の記事ファイル（未公開・予約投稿を含む）から同じ slug らしきファイルを探し、中身を読んで実際の URL を照合 ② 公開中のページに同じ URL があるかを同一オリジンで確認（aliases も対象）。更新時は自分自身を除外 |
| slug の変更 | 未検査 | 既存記事の URL が変わる場合に旧→新を示して警告 |
| categories | ブロック形式のみ許可値を検査 | ブロック・インライン両形式。新規 ja 記事は必須（翻訳版は不要） |
| 投稿後の記事リンク | ファイル名から推定（slug と違う場合に誤ったリンク） | frontmatter の slug／url から算出 |
