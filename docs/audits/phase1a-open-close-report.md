## 3. 仕様の実装内容

### 3.1 状態と年表

| 状態 | 年表のラベル | 件数 |
|---|---|---|
| `open` | オープン（未確認なら「オープン（未確認）」） | 開店（確認済み）に数える（未確認は数えない） |
| `open_planned` | オープン予定（未確認なら「出店予定（未確認）」） | 数えない |
| `close` | 閉店（未確認なら「閉店（未確認）」） | 閉店（確認済み）に数える（未確認は数えない） |
| `close_planned` | 閉店予定（未確認なら「閉店予定（未確認）」） | 数えない |
| `temp_close` | 休業 | 数えない |
| `reopen` | 営業再開 | 数えない |
| `renewal` | リニューアル | リニューアルに数える（日付を過ぎたもの。年月だけなら今月まで） |
| `move` | 移転 | 数えない |
| `popup` | 期間限定出店 | 数えない |
| `feature` | まとめ | 数えない（年表には従来どおり表示） |

- 件数の表示: 「◯件の開店（確認済み）」「◯件の閉店（確認済み）」「◯件のリニューアル」と、注記「（2026年・当サイト掲載分。開店予定・閉店予定・未確認の情報・期間限定出店は含みません）」。「2026年に実際にあった全開店」と読まれないよう、確認済みと掲載分であることを明記した
- 件数は「記事数」ではなく状態変化の件数。同じ店舗の続報・重複記事は yaml の `count: false` で件数から外す（行は残る）。**既存の仕組みは無かった**（yaml は記事ごとの `type`・`when` だけで、記事どうしの関係を持たない）ため、最小限の `count` を追加した。タイトルから同一店舗を推定する仕組みは作っていない
- 今年は日本時間（`date-jst.html`）。件数は日付の分かる行だけ（日付不明は年が分からないので数えない）

### 3.2 予定日経過

- `open_planned`・`close_planned` は予定日を過ぎても自動で `open`・`close` にしない
- 年月日は翌日から、年月だけはその月が終わってから「予定日経過・未確認」（日本時間）。年表・記事の通知・投稿ツールの警告・CI の Summary で同じ判定
- CI の Summary（`validate` ジョブ）に「店舗の予定日経過・未確認（確認用。公開は止めません）」として、記事の `shopStatus` と yaml の `status` の両方を一覧する。失敗にはしない。現在は該当0件（どちらにもまだ値が無い）。補正 PR の案を入れると34件

### 3.3 日付（shopDate）

- 年月日 → その日付で並べる。年月 → その月の「日付未定」に、日付のある行の後ろ。日付なし → 最後の「時期未定」（掲載日で代用しない。掲載日の新しい順に並べる）
- 「下旬」「夏」などから日付・月を作る処理は無い（値そのものの形式だけを読む）
- legacy 記事だけ、時期の代わりに yaml の旧 `when`、yaml も無ければ `eventDate`（`eventDates` の初日）を使う。yaml に新しい `status` を書いた行は `date` だけを見る（旧 `when` は報道月のこともあるため使わない）

### 3.4 legacy 記事の自動分類

`shopStatus` も yaml も無い「開店・閉店」カテゴリの記事だけに使う。判定順（上から）:

1. 閉店していません → まとめ
2. 一時休業｜臨時休業｜一時閉店｜改装休業｜長期休業｜休館｜休業 → 休業
3. 営業再開｜再開（「再開発」を除く）→ 営業再開
4. 移転 → 移転
5. リニューアル｜改装｜新装｜刷新｜業態転換 → リニューアル
6. 閉店・閉院・閉業・営業終了＋予定｜へ｜か → 閉店予定
7. 閉店｜閉院｜閉業｜営業終了 → 閉店
8. 期間限定｜限定出店｜限定ショップ｜「限定◯◯N店」｜ポップアップ → 期間限定出店
9. まとめ｜一覧 → まとめ
10. 予定｜見込み｜〜へ｜〜か｜求人 → オープン予定
11. それ以外 → オープン
12. 補助: 7・11 の結果で、`eventDate` が掲載日より後なら閉店予定・オープン予定（legacy だけ）

`shopUnconfirmed` はタイトル・この補助判定からは立てない（「出店予定か　求人で判明」もラベルは「オープン予定」）。設計時の検証（タイトル規則）で、120本中100本がこの方法で推奨と一致した。

運営者の基準（改装を伴う再開は renewal、単純な再開は reopen、両方なら renewal。同一店舗の業態変更は renewal、別店舗への入れ替えは旧店舗 close＋新店舗 open。判断できなければ要確認）は、補正 PR のデータで適用する。PR 5 本体はデータを変えないため、要確認11本の扱いは補正 PR の確認事項に残す（第9章）。

## 5. マージの順序と互換性

- 補正 PR は yaml に**新しい項目**（`status`・`date`・`unconfirmed`・`count`）を足し、旧 `type`・`when` は書き換えない方式にする（`correction-yaml-draft.tsv` はこの方式）。現行のテンプレート（PR 5 前）は新しい項目を読まないため、どちらを先にマージしても年表は壊れない
- **推奨: PR 5 本体 → 補正 PR の順**。補正 PR は PR 5 の表示（予定・未確認・予定日経過の一覧）で中身を確認できる。逆順だと、補正 PR を入れても PR 5 までは何も変わらず、確認ができない
- PR 5 だけが本番に入った期間は、第4章の暫定値（開店48）が表示される。補正 PR を入れると最終想定値になる

## 10. 記事化プロンプト Stage C への引き継ぎ

PR 5 本番反映後に、店舗記事（開店・閉店カテゴリ）は `eventDate` ではなく `shopStatus`・`shopDate`・`shopUnconfirmed` を書く。プロンプト本体は今回変更していない。

| 状態 | 選ぶとき | frontmatter の例 |
|---|---|---|
| `open` | 開店したことを公式・店舗・現地で確認できた | `shopStatus: "open"`<br>`shopDate: "2026-09-21"` |
| `open_planned` | 開店予定（予定日が未来、または開店をまだ確認していない） | `shopStatus: "open_planned"`<br>`shopDate: "2026-10-19"` |
| `open_planned`＋未確認 | 求人・第三者情報だけ・「〜か」「とみられる」など、公式・店舗・現地で確認できていない | `shopStatus: "open_planned"`<br>`shopUnconfirmed: true`<br>`shopDate: "2026-11"` |
| `close` | 閉店した | `shopStatus: "close"`<br>`shopDate: "2026-09-27"` |
| `close_planned` | 閉店予定（まだ営業中） | `shopStatus: "close_planned"`<br>`shopDate: "2026-09"`（「9月末」） |
| `temp_close` | 一時休業・臨時休業・改装休業（再開予定があっても） | `shopStatus: "temp_close"`<br>`shopDate: "2026-09-28"`（休業開始日） |
| `reopen` | 改装を伴わない休業からの営業再開 | `shopStatus: "reopen"`<br>`shopDate: "2026-10-10"` |
| `renewal` | 改装・業態変更・売場刷新を伴うリニューアルオープン（改装を伴う再開も。同一店舗・事業の継続があるとき） | `shopStatus: "renewal"`<br>`shopDate: "2026-09-17"` |
| `move` | 移転（移転先のオープンを含む） | `shopStatus: "move"`<br>`shopDate: "2026-10-01"` |
| `popup` | 店舗・売場としての期間限定出店（フェア一般は `eventKind: "fair"`） | `shopStatus: "popup"`<br>`shopDate: "2026-10-01"`（出店開始日。期間を `/events/` に載せたいときだけ別に `eventDates`＋`eventKind: "fair"`＋`calendar: true`） |
| `feature` | まとめ・店舗一覧・訂正・施設全体の開業など | `shopStatus: "feature"`（`shopDate` は書かない） |

共通のルール:

- `shopDate` は年月日が分かれば `"YYYY-MM-DD"`、月だけなら `"YYYY-MM"`。「下旬」「末」「夏」「年内」「◯月〜◯月」は日付・月に変換しない。分からなければ書かない（掲載日を入れない）
- `shopUnconfirmed: true` は情報の確度。確定したら外す。閉店・閉院の未確認情報にも使う。タイトルの「〜か」と本文を一致させる
- 予定日を過ぎて開店・閉店を確認したら、既存記事の `shopStatus` を `open`・`close` に、`shopDate` を実際の日に更新し、タイトルの「予定」「〜か」も直す（`lastmod` を更新）。確認できないうちは予定のまま（年表・CI に「予定日経過・未確認」と出る）
- 別店舗への入れ替えは、旧店舗の閉店と新店舗の開店を別の状態として扱う（1記事なら主な状態を書き、もう一方は本文で）
- `shopName`（任意）は年表の表示名。同じ店舗の続報・予告は既存記事を更新し、新しい記事を増やさない
