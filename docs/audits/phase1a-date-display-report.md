## 3. 共通部品の仕様（`layouts/partials/event-dates.html`）

呼び出し: `{{ $ev := partialCached "event-dates.html" $page $page.RelPermalink }}`（結果はページだけで決まるのでキャッシュする。キーは言語ごとに異なる `RelPermalink`）

### 3.1 読む項目

| 項目 | 読み方 |
|---|---|
| `eventDate` | 単日・`開始/終了` の期間。配列（旧書式）なら各要素を単日または期間として読む |
| `eventDates` | 配列の各要素を単日または期間として読む（要素1つでも可）。**配列でない値は読まない**（`invalid` に数える） |
| `eventEndDate` | 文字列の `eventDate` の終了日を上書きする（旧書式。従来のカード・`/events/` と同じ。現在使っている記事は0本） |
| `eventOngoing` | 終了日未定。従来どおり真偽で判定する |
| `eventKind` | `event`／`match`／`fair`。それ以外の値は無視してカテゴリで推定する |
| `notableDate`・`notableDates`・`shopDate`・`openDate`・`closeDate` | イベントではない注目の日。`shopDate` は日付まで確定しているものだけ（`"YYYY-MM"` は使わない。月初などに読み替えない） |

日付の値は、引用符付きの文字列、引用符なしの YAML 日付、時刻付きの値（日付部分だけを使う）を受け付ける。

### 3.2 解釈できない値の扱い

次の値は**その値だけを除外**し、ほかの正しい値は使う。値を推測で直したり補ったりはしない。`time` 関数は `try` で包むので、どの値でもビルドは止まらない。

- 実在しない日付（`2026-02-30`、うるう年でない `2027-02-29`、`2026-13-01`）
- 逆順の期間（`2026-10-05/2026-10-01`）、終了日が開始日より前の `eventEndDate`
- `〜`・`,` の区切り、区切りが3つ以上、`YYYY/MM/DD`、和文の日付（`10月1日`）
- 配列でない `eventDates`・`notableDates`

`/` の前後の空白（`"2026-10-01 / 2026-10-03"`）は、日付そのものは明確なので期間として読む（投稿ツールと CI は PR 1a-1 のとおりエラーにする。従来のカード・`/events/` も空白を除いて読んでいた）。

### 3.3 返す値

| キー | 内容 |
|---|---|
| `spans` | 開催日程（`{start, end}`）。日付順に並べ、同じ日程の重複（`eventDate` と `eventDates` の併用など）を除く |
| `groups` | 表示用の日程。原則 `spans` のとおり（単日は独立した日程、期間の要素はその期間）。**全体が連続する単日だけのとき（例: 8/14・8/15）だけ1つの期間にまとめる**。連続日と飛び日が混在する場合（例: 7/24・7/25・7/27）はまとめない |
| `count` | `groups` の数＝開催日程の数（暦日数ではない） |
| `start`・`end` | 最初の日・最後の日 |
| `days` | サイドバー・`/daily/` で開催日として扱う日。日程ごとに、**14日以下は全日、15日以上は初日と最終日、終了日未定は開始日だけ** |
| `notable` | イベントではない注目の日 |
| `kind`・`kindSource` | 種別と、その根拠（`eventKind`／`category`／なし） |
| `ongoing` | 終了日未定か |
| `invalid` | 除外した値の数 |

### 3.4 種別の判定（調整後）

| 条件 | 種別 | カードのラベル |
|---|---|---|
| `eventKind: "match"` | match | 試合日 |
| `eventKind: "event"` | event | 開催 |
| `eventKind: "fair"` | fair | 期間 |
| `eventKind` が無く、1件目のカテゴリが「イベント」 | event（従来互換） | 開催 |
| `eventKind` が無く、1件目のカテゴリが「スポーツ」 | **推定しない** | なし（従来どおり） |
| `eventKind` が無く、それ以外のカテゴリ（子育て・教育、グルメ・カフェ、開店・閉店、お知らせ、ニュース）・カテゴリなし | 推定しない | なし |

スポーツには試合ではない記事（施設のオープン、表敬訪問、ファン感謝祭、体験会など）が含まれるため、誤った「試合日」を出すより表示の正確さを優先した。`calendar` はカレンダー掲載の制御用で、この部品では扱わない。

## 5. 表示の最終仕様

### 5.1 記事カード（`card-dates.html`）

- 公開日は従来どおり `date`。`datetime` 属性、カテゴリ表示、画像のない記事のアイコン、「公開」の付け方（ラベルがあるときだけ）は工程1b のまま
- ラベルは「日本語ページ」かつ「種別がある」（第3.4節）かつ「解釈できる日程がある」場合だけ出す。店舗の一時休業などの `eventOngoing` 記事（開店・閉店・ニュース）にも付かない

| 種別 | ラベル | 色（既存の CSS 変数） |
|---|---|---|
| event | 開催 | 従来の開催日ラベルの色（`--cat-event`） |
| match | 試合日 | スポーツカテゴリの色（`--cat-sports`） |
| fair | 期間 | グルメ・カフェカテゴリの色（`--cat-gourmet`） |

| 日程 | 表示例 |
|---|---|
| 単日 | 開催 10月17日(土) |
| 連続期間（同じ月は終了日の月を省く） | 開催 8月14日(金)〜15日(土) ／ 9月28日(月)〜10月3日(土) ／ 12月28日(月)〜2027年1月4日(月) |
| 全体が連続する単日だけの配列 | 1つの期間として「開催 8月14日(金)〜15日(土)」 |
| 2〜3日程 | 開催 10月25日(日)・11月3日(火) ／ 7月24日(金)・7月25日(土)・7月27日(月)（混在は結合しない） |
| 4日程以上 | 開催 10月25日(日)ほか全4日程 |
| 終了日未定 | 開催 8月26日(水)から（終了日未定） |

- 年は、1件目が公開日と同じ年なら省く。2件目以降と期間の終了日は、直前の日付と同じ年なら省く（例: 公開 2026年の記事で「2027年1月22日(金)・2月5日(金)」）
- 同じ日程の重複は表示から除く

### 5.2 サイドバーのカレンダー・`/daily/`

- 開催日程は、日程ごとに14日以下は全日、15日以上は初日と最終日、終了日未定は開始日だけを対象にする。`eventDates` の複数会期は会期ごとに同じルール。種別の有無にかかわらず、従来どおり `eventDate(s)` を持つ記事はすべて対象
- `/daily/` は `notableDate(s)`・日付まで確定した `shopDate`・`openDate`・`closeDate` も対象にした（サイドバーで点灯するのに `/daily/` に記事が出ない食い違いを解消。サイドバーにも `shopDate` を追加）。年月だけの `shopDate` は特定の日付として扱わない
- 同じ記事・同じ日の重複は出さない。公開日と注目の日が同じ記事は1回だけ
- `/daily/` の日付バッジ（投稿日と別の日に出る）: 開催日程に一致すれば種別の文言（event「開催日」・match「試合日」・fair「期間中」）、種別が無ければ従来どおり「注目の日」。イベントではない注目の日に一致すれば「注目の日」

### 5.3 終了通知・終了日未定

- 最終日は全日程のうち最も遅い日。今後の日程が残っている複数日程の記事は終了扱いにしない
- 対象: `eventDate` を持つ記事（従来どおり。スポーツ・お知らせなども含む）と、`eventDates` だけを持つ記事のうち種別がある記事（1件目のカテゴリがイベント、または `eventKind` 付き）。スポーツや子育て・教育などの `eventDates` だけの記事には出さない
- 文言の選び方（カテゴリに「イベント」を含めば「このイベントは終了しました」、それ以外は予告記事だけ「◯◯より前に掲載した告知です」）、表示時刻の境界（最終日の翌日0時 UTC＝日本時間 9時。従来の `time` と同じ計算）は変えていない
- `eventOngoing: true` は従来どおり通知を出さない。`notableDate(s)` を持つ記事には終了の通知を追加していない

### 5.4 イベント情報ボックス（`single.html`）

表示条件（`eventDate` があり `hideEventBox` が無い）と `hideEventBox` の扱いは変えていない。日付を生の値ではなく整形して出す（例: 「開催日 2026年10月17日(土)〜18日(日)」。`eventKind: "match"` なら「試合日」）。`eventEndDate` は期間の終了日として開催日の表示に含め、別行の「終了日」はやめた。**現在このボックスを表示している記事は0本**（全記事が `hideEventBox: true`）で、実際の表示は変わらない。

### 5.5 `/events/` の安全対策

開始日・終了日の取り出し方は従来のまま、検証だけを `date-ymd.html` に替えた。実在しない開始日（`2026-02-30` など）の記事は載せない（従来はビルドが止まっていた）。実在しない終了日は開始日と同じ扱い（形式の崩れた終了日の従来の扱いと同じ）。**正常な日付の記事の掲載・順序・表示は変わらない**（生成ページは CSS のファイル名以外 1 バイトも変わらないことを確認）。

- `/events/` は1件目のカテゴリにかかわらず `eventDate` を持つ記事を載せている（スポーツ・お知らせ・開店・閉店を含む）。本 PR でカードの種別推定をイベントだけにしたので、PR 4 で掲載基準を種別（`kind`）と `calendar` に揃える際、スポーツの扱い（`eventKind: "match"` の付与が先か）を決める必要がある
- Event 構造化データは `eventDate` の生の値を出力する（不正な値・期間を含む配列でも検証しない。`time` は呼ばないのでビルドは止まらない）。`eventDates` だけの記事には出さない。主催者・会場の既定値「浦安市」も従来どおり
- 推奨: 両方を `event-dates.html` に切り替え、`kind` と `calendar` で掲載を決める（設計書第4・6章）

### PR 5（開店・閉店年表）

- `shopStatus`・`shopUnconfirmed` はまだどの表示にも使われていない。`shopDate` は日付まで確定したものだけ、サイドバーと `/daily/` の「注目の日」に使う
- 開店・閉店記事の `eventDate` はカードのラベルを出さないが、サイドバー・`/daily/` では従来どおり（期間は今回のルールで）対象になる
- `openDate`・`closeDate`（旧項目）は注目の日として読み続けている

### その他

- ガイド記事の `factChecked` は `meta-badges.html`・`source-info.html` が `time` で直接変換するので、不正な値でビルドが止まる。posts ではなく投稿ツールの検証対象外。`shortcodes/happy-entry-excluded.html` は `data/` の手作業管理のデータを変換する。いずれも本 PR の範囲外
- 「サイドバーの重複記事表示の解消」「同一イベントを扱う複数記事の統合」「多言語ページの日付書式」は指示書どおり対象外
